# 0.2.0 审查与验证记录

## 首轮实现中修复的缺陷

每项都先有失败用例，再修复：

- 复用回退忽略显式关闭动画；
- 禁用路由的等待目标域与兜底执行域不一致；
- 跨目标域确认后沿用旧来源；
- 修改 URL 配置后未归一化大小写；
- 模态关闭通知晚于导航栈释放时漏清理；
- 已被其他窗口或展示关系接管的页面被误清理；
- 原宿主释放后漏通知；
- 转场回调缺失时强快照滞留；
- 路由器释放后客户端三个操作结果不一致。

## 第二轮审查结论与处理

第二轮审查中，下列问题先写复现用例，确认在首轮实现上失败，再修复。

| 问题 | 处理 |
|---|---|
| 登录（无会话 → 有会话）后已创建的 `LYRouteClient` 全部失效，已接管的模态栈被拆除 | 客户端改为绑定会话代次，登录保留；登录时保留已接管的模态栈 |
| 选中 Tab 不是导航栈时，不带来源的请求被拒绝 | 恢复 0.1.1 的宿主当前域准入 |
| 宿主未就绪会终止展示中的执行 | 只终止准备阶段 |
| 显式来源的结果值不一致 | 统一结果表：失效来源对用户忽略、对外部失败；被覆盖来源对用户忽略、对外部等待 |
| 栈顶页面的子控制器不能作为来源 | 归一为所在页面 |
| 等待请求被丢弃时没有任何事件 | 新增 `routeDidDropPending` 与 `LYPendingDropReason` |
| 模态关闭时整栈清理，与主栈语义不一致 | 只有 `LYRouteClient.dismiss` 关闭时清理 |
| `present` 接管系统导航控制器 | 排除相册、视频编辑、邮件、短信 |
| `LYTabBarHost` 把导航代理方法转给 Tab 代理；`attach` 不重装 Tab 代理 | 按协议分别转发；`attach` 时重新接管 |
| 未接管模态中 `back` 与 `dismiss` 准入不一致；`context.navigationController` 不跟随 `revealExisting` | 统一准入；改为读取实时目标栈 |

## 文档说明（不改变语义）

- 重定向后，观察者只收到目标路由的事件。
- `prepare` 之后必须先 `await isStillValid()` 再展示，路由器不会自动检查。
- URL 末尾斜杠会被忽略。
